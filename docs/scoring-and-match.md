# 计分结算与多局状态机

## 计分原则

计分模块不内置未经确认的鄱阳分值。创建比赛时必须显式提供：

- 底分；
- 每个已识别牌型的番数；
- 自摸加番；
- 抢杠胡加番；
- 最大番数；
- 单次支付封顶；
- 自摸支付倍率；
- 点炮者支付倍率；
- 庄家倍率。

如果胡牌结果包含未配置的牌型，结算会失败并指出缺少的牌型，不会按零番或猜测分值继续。

## 计算顺序

1. 汇总胡牌结果中的牌型番数；
2. 加入自摸或抢杠胡附加番；
3. 应用最大番数；
4. 按 `底分 × 2^总番数` 计算单次支付基础；
5. 应用单次支付封顶；
6. 应用自摸/点炮及庄家倍率；
7. 生成玩家之间的支付明细；
8. 校验四家分数变化之和为零。

计分结果同时包含番数拆分、支付明细、单局分差，便于结算页面展示和牌局审计。

## 支付模型

- 自摸：其他三家分别向赢家支付；
- 点炮：点炮者向赢家支付；
- 抢杠胡：补杠声明者作为输家向赢家支付；
- 流局：默认不产生分数变化。

所有倍率均由比赛配置决定。

## 多局比赛状态机

~~~text
BETWEEN_ROUNDS
  -> ROUND_IN_PROGRESS
  -> BETWEEN_ROUNDS
  -> ...
  -> MATCH_SETTLEMENT
~~~

比赛状态机负责：

- 生成递增、唯一的单局 ID；
- 保存当前庄家；
- 限制总局数；
- 调用计分模块；
- 累计四家总分；
- 保存每局结果和结算历史；
- 根据配置决定连庄或轮庄；
- 达到局数后进入总结算。

## 庄家策略

可配置三种策略：

- `WIN_ONLY`：庄家胡牌时连庄；
- `WIN_OR_DRAW`：庄家胡牌或流局时连庄；
- `NEVER`：每局结束后轮庄。

鄱阳本地的最终连庄口径确认后，只需选择或扩展策略，无需修改单局引擎。

## 当前仍需业务确认

- 各牌型实际番数；
- 自摸、点炮和抢杠胡是否额外加番；
- 底分和封顶；
- 庄家倍率；
- 点炮者是否包三家；
- 流局是否查花猪、查叫或产生其他赔付；
- 总局数以及连庄是否计入局数上限。
