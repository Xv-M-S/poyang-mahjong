# 单局引擎开发说明

## 已实现范围

- 136 张标准牌墙校验；
- Fisher–Yates 洗牌；
- 正式对局的系统安全随机源；
- 测试和回放使用的种子随机源；
- 从庄家开始的三轮四张发牌、每人补一张、庄家再补一张；
- 庄家 14 张、闲家 13 张、牌墙剩余 83 张；
- 服务端权威版本号；
- 出牌、响应窗口、无人响应、下一家摸牌；
- 自摸胡、接炮胡的合法牌型校验；
- 牌墙耗尽后流局；
- 只追加的单局事件序列；
- 每次状态变化后的 136 张牌守恒检查。

## 单局流程

~~~text
创建牌局
  -> 洗牌
  -> 发牌
  -> 庄家出牌
  -> 响应窗口
     -> 无人响应 -> 下一家摸牌 -> 出牌
     -> 接炮胡 -> 单局结算
  -> 自摸胡 -> 单局结算
  -> 牌墙耗尽 -> 流局结算
~~~

## 随机数约束

`createShuffledWall()` 使用运行环境提供的密码学安全随机源。若环境没有安全随机源会直接失败，不会静默降级到 `Math.random()`。

`createSeededWall(seed)` 只用于自动化测试、问题复现和回放。种子洗牌可预测，不能用于正式对局。

## 版本与幂等边界

每个操作必须携带客户端看到的 `expectedVersion`。版本不一致时，引擎返回 `STALE_VERSION`，调用方应重新获取快照，不能盲目重试旧操作。

当前引擎以单进程内存对象实现规则与状态变更。后续接入实时服务时，房间服务负责：

- 对 `requestId` 做幂等去重；
- 将同一房间固定路由到同一节点；
- 把引擎事件持久化到牌局事件表；
- 分离公开摸牌事件和仅对本人发送的私有牌面事件；
- 在响应窗口中加入吃、碰、杠的多人优先级裁决。

## 暂未实现

- 吃、碰、明杠、暗杠、补杠；
- 多人响应收集和优先级裁决；
- 抢杠胡、一炮多响；
- 杠后补牌；
- 番数和最终分数结算；
- 超时托管及断线恢复。

这些能力将在下一阶段建立在当前事件与版本模型之上。
