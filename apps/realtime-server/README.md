# Realtime Server

鄱阳麻将的服务器权威实时房间服务。

## 当前能力

- WebSocket 房间连接与协议心跳；
- 六位房间号、创建、加入、准备、房主开局；
- 四名真实玩家的公开状态与私人手牌隔离同步；
- 客户端只提交动作，服务端调用规则引擎进行版本校验和权威裁决；
- 摸牌、出牌、吃、碰、明杠、暗杠、补杠、胡、抢杠胡与多局结算；
- 房间版本、请求 requestId 幂等与过期版本恢复；
- 操作倒计时、响应窗口超时自动过牌和玩家超时托管；
- 掉线检测、指数重连、重新上线后自动找回房间；
- 房间、完整牌墙、私人手牌、比赛历史与幂等结果的本地原子快照；
- 服务进程重启后恢复未结束牌局；
- 结束后再来一场、主动退出和房主解散房间。

## 开发启动

在仓库根目录执行：

    npm run start:realtime

默认地址：

    ws://127.0.0.1:8080?userId=<development-user-id>

默认运行数据保存在 apps/realtime-server/.data/，该目录不会提交到 Git。

## 配置

| 环境变量 | 默认值 | 说明 |
| --- | ---: | --- |
| HOST | 127.0.0.1 | 监听地址；局域网真机联调可使用 0.0.0.0 |
| PORT | 8080 | WebSocket 端口 |
| DATA_DIRECTORY | apps/realtime-server/.data | 房间与幂等快照目录 |
| TURN_TIMEOUT_MS | 30000 | 摸牌/出牌操作时限 |
| REACTION_TIMEOUT_MS | 12000 | 吃碰杠胡响应时限 |
| HEARTBEAT_INTERVAL_MS | 15000 | WebSocket 心跳间隔 |

测试可省略 dataDirectory，此时使用内存仓库，避免产生运行文件。

## 恢复与安全边界

开发版通过原子 JSON 快照完成单进程重启恢复；仓库接口已经与房间领域逻辑解耦，部署多实例时应将其替换为 PostgreSQL/Redis 实现，并增加分布式锁或单房间 actor 路由。

当前 userId 从 WebSocket 查询参数读取，只用于本地联调。正式环境必须改为 API 服务签发的短期连接票据，并使用 wss://。
